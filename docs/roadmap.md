# DSH 无痕对话开发路线图

目标是在 DSH 主界面开启临时对话，正常发送消息、调用工具和走审批。无痕会话的内容、标题和用量不写入 DSH 的会话存储，删除后释放内存。消息仍会发给所选模型服务商，工具对外部文件的操作仍然生效。会话打开时，工作区会暂存会话 ID，删除时清理，异常退出后由下次启动清理。

## 1. 验收已安装的 preview.2

隔离环境已验证基本对话不落盘，真实桌面版已安装 preview.2，重启后仍待验收。侧栏标识和手动删除已实现，本阶段验证它们在真实桌面版是否工作。

- 从托盘退出并重启 DSH。新建无痕对话，用专用探针文字测试消息、工具调用和会话切换。确认切换后能回来，手动删除后侧栏条目消失。
- 检查会话目录和投影缓存没有探针。删除后检查工作区 ID 和对应浏览器存储，必要时在隔离环境确认 host 内存已释放。再用另一段普通会话探针验证检测脚本确实能找到落盘内容。
- 若桌面版和隔离环境表现不同，先记录版本和复现步骤，再决定是否修复。

学习任务：从 `src/host/ids.js` 和 `tests/ids.test.mjs` 开始。先一起读一条示范测试，再由 shin 逐条完成四个 TODO，并试着移除正则开头的 `^`，观察能否用测试抓到错误。

## 2. 封住附件留盘路径

先跟踪文件选择、拖拽和粘贴图片分别何时触发保存，尤其确认新建页上的上传是否早于会话创建。当前建议是先在无痕模式明确禁用附件。若无法在写入前可靠区分模式，就先定位可用的拦截点，再决定方案。已经暂存附件后切到无痕的情况也要纳入设计。

验收时覆盖三种入口与模式切换，确认无痕尝试不会新增附件文件，普通会话仍能上传和发送。学习时选一个入口，沿着“用户操作 → 上传请求 → 写文件”读源码，由 shin 找出第一处写盘的位置。

## 3. 确认会话日志是否随请求发送

查清 `session-log-deepseek` 的触发条件和请求组装位置。若无痕会话会附带额外日志，就在组装请求时针对无痕 ID 跳过这部分。使用合成探针，在隔离环境检查实际请求结构，区分正常对话消息和额外会话日志，并用普通会话做对照。

## 4. 调整开关并准备下一预览版

把开关移到「标准模式」紧后面，优先使用 DSH 提供的插槽。确认位置、键盘操作及插件自检失败时的禁用状态。最后回归消息、工具调用、会话切换、删除、重启和普通会话对照，更新 README 中的无痕边界，再决定是否发布。

每次只推进一个学习点。练习由 shin 动手，开发任务按上面的验收条件逐项验证。当前第一步是读懂示范测试并完成第一条 TODO，随后安排桌面验收。
